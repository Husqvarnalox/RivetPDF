# Rivet QA report — October 2026

Scripted end-to-end QA pass of the Rivet shell (PDF + Markdown) using the
`RIVET_QA_SCRIPT` harness (`src/app/QaScript.{hpp,cpp}`, scenarios under
`tools/qa/scenarios/`). Every screenshot named below was produced by the
harness and inspected by eye; screenshots are written to `build/qa-shots/`
and are not committed (regenerate them with the commands in
"Reproducing").

## Environment

- Host: macOS, Darwin 25.6.0, Apple Silicon, Retina (2x; shots are
  2560x1700 for a 1280x850 window).
- Main pass: `build/p-on` (Debug, `-Werror`, PDFium ON), scenarios 01–11.
- Sanitizer pass: `build/p-asan` (ASan+UBSan, PDFium ON), scenarios 01–10
  re-run, plus the crash backtrace for 11.
- Engine-less pass: `build/p-off` (PDFium OFF), scenario 12.

**Linux was not run.** `tools/qa/linux-qa.sh` (Docker `ubuntu:24.04`, GCC,
Xvfb 1920x1200, PDFium OFF — no Linux PDFium binary exists here) is
committed, but the image could not be pulled on this host: `docker run`
hung for over 20 minutes and then failed with "error getting credentials -
err: signal: terminated" (the Docker credential helper never answered),
although Docker Hub itself was reachable. The Linux screenshot/resize
hooks (`X11Window::writePng`, `resizeContent`) therefore compile only in
CI and have not been exercised. Scenarios 10 and 12 are the intended Linux
pass. For the same reason the llvm-mingw Windows cross build was not run.

Windows: the harness is wired into `src/platform/windows/main.cpp` (scripts,
dialog doubles, exit codes) but has no screenshot or resize hook; no Windows
run was performed.

The harness runs against the user's real application data (preferences and
the Recent list), so the welcome screen shows whatever the user opened last.
Fixtures are generated by `tools/qa/make-fixtures.sh` into
`build/qa-fixtures/`; working copies go to `build/qa-work/`.

## Reproducing

```
tools/qa/make-fixtures.sh
tools/qa/run-qa.sh build/p-on/src/platform/macos/rivet tools/qa/scenarios/*.rivetqa
# Linux (from the repository root):
docker run --rm -v "$PWD":/src:ro -v "$PWD/build/linux-qa":/out ubuntu:24.04 bash /src/tools/qa/linux-qa.sh
```

`run-qa.sh` writes `<scenario>.log` next to the screenshots. A scenario
exits 0 when every step and assertion passed, 1 when an assertion failed,
2 on a script/harness error (parse error, idle timeout, missing hook).

## Bugs

Severity: blocker (crash/data loss in a primary workflow), major (primary
workflow visibly wrong), minor (works but misleading/awkward), cosmetic.
"Repro" names the scenario file and line under `tools/qa/scenarios/`.

### 1. BLOCKER — Markdown "Export as PDF" crashes when no PDF was opened in the session

- Repro: `11-markdown-export-crash.rivetqa` line 10 (open a `.md` file in a
  fresh process, File > Export as PDF…, choose a target). Deterministic.
- Expected: a PDF is written.
- Actual: SIGSEGV on the export worker thread; the app dies. A 0-byte
  `.<name>.pdf.rivet-XXXX.tmp` file is left next to the target.
  If any PDF was opened earlier in the same process, export works
  (scenario 09 relies on that).
- Backtrace (`build/p-asan`, ASan):
  ```
  AddressSanitizer: SEGV on unknown address 0x000000000000 (READ)
  #0  CPDF_ColorSpace::GetStockCS          core/fpdfapi/page/cpdf_colorspace.cpp:477
  #1  CPDF_ColorState::SetDefault          core/fpdfapi/page/cpdf_colorstate.cpp:160
  #2  FPDFPageObj_CreateNewRect            fpdfsdk/fpdf_editpath.cpp:73
  #3  rivet::pdf::addRect                  src/pdf/pdfium/PdfiumBuilder.cpp:139
  #4  rivet::pdf::buildPage                src/pdf/pdfium/PdfiumBuilder.cpp:270
  #5  rivet::pdf::buildWithPdfium          src/pdf/pdfium/PdfiumBuilder.cpp:303/310
  #6  rivet::pdf::PdfiumEngine::buildDocument  src/pdf/pdfium/PdfiumEngine.cpp:136
  #7  writeBuild (MarkdownExportController.cpp:69/71, via writeFileAtomically)
  #8  export task                          src/app/MarkdownExportController.cpp:218
  ```
- Likely cause: PDFium is never initialised on this path.
  `PdfiumLibrary::instance()` (which calls `FPDF_InitLibraryWithConfig`)
  runs only in `PdfiumEngine::openDocument` (`PdfiumEngine.cpp:75`), not in
  `buildDocument`, so the stock colour spaces are still null.
  Secondary: the failed write leaves its temp file behind.
- Screenshots: none (the process dies).

### 2. MAJOR — Default zoom ("fit width") overshoots; page clipped with a horizontal scrollbar

- Repro: `01-navigation.rivetqa` line 9 (open), line 47–50 (zoom menu > Fit
  Width); `10-welcome-resize.rivetqa` lines 22, 28.
- Expected: the page width fits the viewport, no horizontal scrollbar.
- Actual: sample.pdf (Letter) opens at 173% in a 1280x850 window, 118% at
  940x600, 225% at 1600x1000; small pages (300x400 pt form/rich fixtures) at
  353%. The right edge of the page is cut off and a horizontal scrollbar
  appears. Choosing Fit Width in the zoom popup gives the same 173%. The
  Compare panes show the same overshoot.
- Screenshots: `01-open-initial.png`, `01-fit-width.png`,
  `10-pdf-940x600.png`, `10-pdf-1600x1000.png`, `08-compare.png`.

### 3. MAJOR — View menu has no zoom commands

- Repro: any PDF; inspect the View menu (`01-navigation.rivetqa` line 47
  uses the toolbar zoom popup because no menu item exists).
- Expected: View > Zoom In / Zoom Out / Actual Size / Fit Width / Fit Page.
- Actual: none of these are in the menu bar; they exist only as toolbar
  buttons, keyboard shortcuts and the zoom popup (which has Actual Size ⌘0,
  Fit Width, Fit Page and percentages). The menu bar also lacks Find, Copy,
  Select All and Print entries, so these are not discoverable from menus.
- Screenshots: `01-zoom-menu.png`.

### 4. MAJOR — Form fields render blank after their value changes

- Repro: `05-forms.rivetqa` lines 16–23 (type into text fields, Tab),
  35–37 (pick a list item), 40–43 (pick a combo item), 46–50.
- Expected: the new value is drawn in the field (page and thumbnail).
- Actual: once focus leaves the field, the field is drawn empty in the
  viewport and the thumbnail. The values are stored correctly — after save

- Screenshots: `05-text-filled.png`, `05-combo-picked.png`,

### 5. MAJOR — Markdown Cmd+B with a collapsed caret selects the previous word; next keystroke replaces it

- Repro: `09-markdown.rivetqa` lines 46–56 (type " more words", Cmd+B, type
  "bold", Cmd+B, type " plain").
- Expected: Cmd+B with no selection toggles bold for the text typed next
  (or bolds the word without selecting it).
- Actual: the previous word ("words") becomes bold *and selected*; typing

  The line ends as "more  plain" — typed text is lost without warning.
- Screenshots: `09-edit-cmdb.png`, `09-edit-typed-bold.png`,
  `09-edit-cmdb2.png`, `09-edit-source.png`.

### 6. MAJOR — Markdown→PDF export draws math letters as tofu and drops italics

## Fix log

Markdown/UI findings (the original findings above are kept unchanged).

- **#5** Fixed in a1543ba. `toggleInline` with a collapsed caret never
  selects or rewrites text: it inserts an empty pair with the caret inside
  (`**|**`), removes such a pair when toggled again, and steps past the
  closing delimiter it sits before (`**bold|**` -> `**bold**|`); the same for
  Italic, Strikethrough, Code and Link (`[|](url)`). Unit test
  `inlineFormattingWithCollapsedCaretNeverSelects`; scenario 09 asserts the
  caret after each Cmd+B/Cmd+I (`assert-md-caret`, `assert-md-source`).
- **#6** Fixed in dcdda9a. Root cause: the builder set run text with
  `FPDFText_SetText`, whose Unicode -> char code lookup for the CID-keyed
  bundled fonts only knows BMP code points, so the Mathematical Alphanumeric
  Symbols (U+1D400...) became char code 0 (.notdef). The Noto Sans Math
  subset already covered them (`subset_fonts.py --set math` unchanged).
  Runs are now written with `FPDFText_SetCharcodes` and the glyph ids of the
  cmap `BundledFontMetrics` measures with. `PdfBuildText::skew` (validated,
  text matrix `{1,0,skew,1,x,y}`) gives `*emphasis*` a ~12 degree synthetic
  oblique in the export, matching the preview. PDFium-ON tests
  `builderWritesSupplementaryPlaneMathGlyphs` and
  `markdownExportMathLettersHaveGlyphsThroughPdfium` (fail before the fix).
  Remaining limitation: `PdfTextPage` reports each UTF-16 half of such a
  letter as U+FFFD, so math letters are not searchable/copyable.
- **#9** Fixed in 4f3317a. Return pressed while the search had no result yet
  (typed right after the query) stepped an empty match list; the step is
  now deferred until the first match arrives. Scenario 01 asserts "1 /"
  then "2 /" (the double-Return workaround is gone).
- **#10** Fixed in 4f3317a. Cmd+F selects the previous query
  (`TextField::selectAll`). Scenarios 01/08 assert it with
  `assert-find-query`; the `key cmd+a` workaround is gone.
- **#11** Fixed in 7a1f5e5. Tool hints are transient (`StatusBarController::
  setHint/clearHint`, `ShellContext::showHint/withdrawHint`): the crop hint
  ends with the crop tool, the Edit-tool hints when the selection is cleared
  or the content tool changes, any hint on a tool-mode switch (a tab switch
  already replaces the status). Scenarios 02/04 `refute-status`.
- **#14** Fixed in a6840af. Switching Rendered/Source/Split carries the
  caret/selection of the view the user worked in over to the newly shown
  view(s) (the rebound source pane used to reset it); scroll handling is
  unchanged. Scenario 09 asserts the caret across Cmd+2/Cmd+3/Cmd+1.
- **#15** Fixed in 0beacb5. `IMainThreadDispatcher::postDelayed`: macOS
  `dispatch_after` on the main queue, Windows a `WM_TIMER` on the
  dispatcher's message window, Linux the event loop's `poll()` timeout
  (both over the portable `core::DelayedTaskQueue`). The caret blink and the
  tooltip delay use it; no worker sleeps and `ShellController::idleBlocker`
  no longer discounts sleeping tasks (QA idle waits now require an idle
  pool while an editor is focused, which scenario 09 exercises). Unit tests
  `delayedTaskQueueRunsDueTasksInDeadlineOrder`,
  `wysiwygCaretBlinkUsesMainThreadTimers`.
- **#19** Fixed in 4321cba. `ui::Card` with new `cardBorder`/`cardShadow`
  tokens (ADR-0033): rounded panel fill, 1 px border, soft drop shadow
  painted by the parent outside the card's clip (`Widget::paintBehind`).
  Used by the signature sheet, password card, note editor and find bar.
  Test `cardPaintsShadowOutsideItsFrameAndABorder`; screenshots
  `07-sign-sheet.png`, `08-password-prompt.png` re-checked.
- **Harness side effect** Fixed in 8ccbbeb. All three `IAppDataLocation`s
  honour `RIVET_APP_DATA=<absolute dir>`; a run with `RIVET_QA_SCRIPT` and
  no override uses `<temp>/rivet-qa-appdata`. `run-qa.sh` gives every
  scenario a fresh `build/qa-appdata/<scenario>`.


Validation of these fixes: macOS p-off, p-on, p-asan, p-tsan build with
zero warnings and ctest is 100% green (10/10) in each; Linux Debug (GCC,
Docker ubuntu:24.04, PDFium OFF) builds with -Werror, ctest 9/9, scenarios
10 and 12 pass; the llvm-mingw Windows cross build (PDFium OFF) builds with
zero warnings (not run). macOS p-on scenarios 01-04 and 06-11 pass; 05
still fails on bug 7 (not part of this fix set).
